# Hard set: large repositories, Java, and Go/Rust reliability, 2026-11-04

The 55-query Python and Go/Rust sets were close to their ceiling after the
response-budget and whole-declaration changes, so this pass adds what they could not
measure: repositories above one million tokens, a third language family (Java) and
hand-written Go/Rust questions with no answer or a false premise. Datasets are
described in [`real-tasks/README.md`](../real-tasks/README.md#large-repository-tasks-hard-set).
Raw outputs: [`hard-set-2026-11-04-dev.json`](hard-set-2026-11-04-dev.json),
[`hard-set-2026-11-04-heldout.json`](hard-set-2026-11-04-heldout.json),
[`hard-set-2026-11-04-reliability-dev.json`](hard-set-2026-11-04-reliability-dev.json),
[`hard-set-2026-11-04-reliability-heldout.json`](hard-set-2026-11-04-reliability-heldout.json)
(one row per query; a query re-queued after a provider incident keeps its last attempt).

## Setup

- Jev 1.13 through two routes, because the TypeSafe account ran out of credits
  (HTTP 402) in the middle of the pass: `typesafe-direct` / `jev-1.13.0` at concurrency 8
  for the reliability set, prometheus, nushell, 2 lombok, 6 hugo and 2 ruff queries, then
  `vercel-ai-gateway` / `typesafe-ai/jev` at concurrency 16 for the remaining 6 lombok,
  1 hugo, 7 ruff and 8 lucene queries. Same model, same scores within pass-to-pass noise.
- Score cache disabled, threshold 0.5, response budget 8,000 tokens, scan deadline
  raised to 20 minutes.
- One pass per split (a full scan of lucene costs about 0.25 USD per query).
- Held-out splits ran with `--frozen` against a manifest written by `--freeze` before
  the dev run. The queries left unfinished by the outage were frozen again with the
  Gateway configuration and run `--frozen`; nothing was tuned in between (same source
  revision, `2c7dfd8`).
- Per-run token pool (`--max-input-tokens`) of 30M on the first dev pass; the queries it
  rejected or left not-run were re-queued in later passes with a 400M pool.

```sh
npm run bench:real -- --hard --config <trusted-config> --response-tokens 8000 --split dev
npm run bench:real -- --hard --config <trusted-config> --response-tokens 8000 --split heldout --frozen <freeze.json>
npm run bench:real -- --manifest benchmarks/real-tasks/hand-go-rust-reliability-1.json --config <trusted-config> --response-tokens 8000 --split dev
```

## Results: Go/Rust reliability set (16 queries)

| Category | Queries | Correct | Repositories |
|---|---:|---:|---|
| `false-premise` (counter-evidence returned, R@5) | 9 | 9 | caddy 2, bat 2, gin 3, axum 2 |
| `no-answer` (no excerpt returned) | 7 | 4 | gin 2/2, axum 2/2, bat 0/1, caddy 0/2 |

R@1 on the false-premise queries is 0.75 (dev) and 0.60 (held-out): the contradicting
code is always inside the returned excerpts, not always first. Cost and time per query
follow the repository size: 0.001 USD / 0.9 s on bat (28k tokens) to 0.009 USD / 6.3 s
on axum (220k tokens).

The three abstention failures share one pattern. Jev scores code that is *about* the
subject of the question, but does not do what the question asks, between 0.60 and 0.74,
above the 0.5 threshold:

| Query | Returned instead | Top score |
|---|---|---:|
| caddy: native YAML config parsing | `caddyconfig/load.go` (config loading via adapters) | 0.74 |
| caddy: admin API bearer/password auth | `admin.go` (admin listener and origin checks) | 0.63 |
| bat: git blame annotations in the gutter | `src/printer.rs` (git modification markers) | 0.63 |

On gin and axum every fragment stays under 0.2 and JevGrep answers "nothing found".
The failures are the questions whose subject has a near neighbour in the code (config
loading, admin security, git decorations); a question about a feature with no neighbour
abstains correctly. Raising the threshold to 0.75 would fix these three and break
positive queries whose evidence scores 0.6–0.75 (common on Go/Rust in the earlier
sets), so the threshold stays at 0.5.

What the completed queries say:

- Recall does not collapse with size. Every repository between 1M and 7.6M tokens
  lands between R@5 0.78 and 0.92; the held-out split (0.864) is above the dev split
  (0.833), and above the 0.83 of the small Go/Rust set. File recall is 0.96–1.00: the
  right file is nearly always in the answer.
- Java is the weak language for ranking, not for recall: lombok has R@5 0.781 but
  R@1 0.208. The evidence is returned, behind other fragments of the same file.
- Four of the five misses are response-budget misses, not scoring misses. The
  evidence file is in the answer (file recall 1) and the expected lines scored above
  the threshold, but did not fit in 8,000 tokens next to many other qualifying
  fragments: nushell-12950 (10 above threshold, 2 omitted), lombok-3594 (133 above,
  124 omitted), hugo-12448 (168 above, 160 omitted), lucene-12022 (78 above, 70
  omitted). Large repositories have more near neighbours above 0.5 per question, so
  the budget, and the order inside it, decide more often than on small repositories.
  The only scoring miss is ruff-15356 (file recall 0).
- Time is the cost that scales, and it is not the provider's price: 0.04–0.25 USD per
  full scan. Through the Gateway a 1.4M-token prometheus query takes 20–24 s at
  concurrency 8, 16 or 32 alike (the direct route took 8 minutes the day before, with
  two queries sharing one key). On lucene (7.6M tokens) a 6–7 minute query spends most
  of its time locally: tokenization 170–216 s, batching 150–183 s and preparation
  30–237 s per query, against 100–215 s of provider time spread over 16 connections.
  Both local stages were quadratic in the number of questions per batch and lines per
  window; they were fixed on `main` after this pass (commits `4f6c172`, `1cb83a6`,
  `f485bb1`: cold `inspect` of prometheus 89 s → 22 s, identical fragments and
  batches). The live timings above are from before those commits.
- The `SCOPE_EXCEEDS_SCAN_BUDGET` rejection seen on lombok in the first pass is a
  benchmark artefact: the 30M-token pool of the run had 0.44M left and the query
  needed 1.0M. It is listed because the same preflight is what a user sees when a
  scope exceeds their cap.

## Limits

- One pass per split; Jev scores vary from pass to pass (R@5 moves by ±0.02 on the
  smaller sets). Two routes to the same model were used within one pass.
- Three queries are not counted: `ruff-15394:understand` (TypeSafe credits),
  `lucene-13494` (Gateway budget) and `lucene-13170` (20-minute deadline, partial).
  They stay in the planned denominator; incidents are not retried silently.
- Three repositories had fewer eligible tasks in SWE-bench Multilingual than planned
  (prometheus 7 of 8, hugo 6 of 7, lucene 8 of 9); the import keeps what exists.
- The reliability set is 16 hand-written questions by one author; it is a probe of
  the two failure modes, not a calibrated estimate of their rates.
- Timings mix two routes and two days; they show orders of magnitude, not a
  controlled latency benchmark.
